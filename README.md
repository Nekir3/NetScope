# NetScope

Консольная диагностика сетевого трафика: проверяет, **что именно происходит с вашими пакетами** — фильтруют ли их, подменяют ли, вскрывают ли TLS, и какие обходные транспорты (Tor-мосты) у вас остаются рабочими.

Программа не делает выводов о причинах. Она измеряет и показывает факты.

## Что она проверяет

| Секция | Что измеряется |
|---|---|
| `env` | адаптеры, системный прокси, VPN/TUN, MTU, маршрут по умолчанию |
| `dns` | ответы системного резолвера против DoH-эталона, перехват, Transparent DNS, EDNS0 |
| `tcp` | достижимость портов 80/443/8080/8443/9001/9050 и признаки фильтрации по порту |
| `http` | коды ответов, подставленные заголовки, скорость, QUIC |
| `tls` | версии, сертификаты, цепочка доверия, видимость SNI, ECH |
| `dpi` | RST-инъекции, устойчивость к фрагментации, 13 вариантов обфускации SNI |
| `mitm` | один CA на несвязанные домены, маркеры перехвата, локальные корневые сертификаты |
| `leaks` | внешний IP, DNS-резолвы, WebRTC/STUN, IPv6, список адаптеров |
| `geo` | страна по трём сервисам, часовой пояс, TTL-аномалии |
| `bridges` | достижимость ваших obfs4/snowflake-мостов, RST-инъекции на их портах |

## Запуск

```bat
run.bat --mode quick
run.bat --section dns,dpi
run.bat --html report.html --json report.json --verbose
run.bat --bridges "obfs4 1.2.3.4:443 ABCDEF... cert=..."
```

Первый запуск собирает проект (около минуты), дальше — сразу.

## Опции

```
--mode quick|standard|deep   глубина прогона (по умолчанию standard)
--section id,id             прогнать только эти секции
--domain пример.рф          добавить домен в проверку (можно несколько раз)
--bridges "строка"          мост Tor для проверки (можно несколько раз)
--fetch-bridges             взять мосты с bridges.torproject.org
--json out.json             полный отчёт в JSON
--html out.html             отчёт-страница в HTML
--timeout мс                таймаут соединений (по умолчанию 4000)
--plain                     без live-интерфейса, логи построчно
--no-color | --ascii        без цвета / без Unicode-символов
--verbose                   показать все детали в итоговом отчёте
--list-domains              показать используемые списки и выйти
--certs                     только сертификаты: какие недоступны, чему нельзя доверять
-h, --help | -v, --version
```

Код возврата: `0` — чисто, `1` — есть замечания, `2` — подтверждённое вмешательство.

## Сертификаты

```bat
run.bat --certs
run.bat --certs --domain example.org --domain cloudflare.com
run.bat --certs --json certs.json --html certs.html
```

Список всех проверяемых доменов со статусом: **доступен** / **без доверия** / **недоступен**. Недоступные стоят первыми, у каждого — причина (таймаут, RST, DNS-ошибка, разрыв хендшейка). Для доменов, где сертификат получен, показывает срок, ЦП, алгоритм подписи, длину цепочки и SHA-256; маркеры перехвата (mitmproxy, Zscaler, антивирусные CA) подсвечиваются отдельно.

В обычном прогоне недоступные сертификаты видны в секции `tls` — проверка «Недоступные сертификаты».

## Списки целей

Редактируйте `src/main/resources/netscope/domains.txt`. Секции задаются строками вида `@suspect`, ниже — по одному домену в строке; `#` — комментарий.

```
@control
cloudflare.com
google.com

@suspect
example.org
```

## Сборка вручную

```bat
gradlew.bat build
gradlew.bat installDist
```

Требуется JDK 21. Зависимости: `kotlinx-coroutines-core`, `net.java.dev.jna`.

## Границы измерения

Программа не обходит блокировку и не является клиентом Tor: она проверяет проходимость и ищет признаки вмешательства в ваш собственный трафик. Обфускацию (obfs4, snowflake) она оценивает по тем же признакам — доступен ли порт, не подбрасывается ли RST.
